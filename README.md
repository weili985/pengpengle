# 碰碰乐 · PengPengLe

一个纯静态的单词配对记忆小游戏：点开即玩、断网可玩、可装到手机桌面，也能打包成离线 APK。
每张英文卡都配一张对应的中文卡，点两张配对，配错就抖一下，全部配完通关。

**在线试玩**：https://weili985.github.io/pengpengle/

---

## 玩法

- 一个词生成一对牌（英文卡 + 中文卡），打乱铺成网格。
- 配对成功：两张一起消失、得分 +10、连击 +1、播成功音。
- 配对失败：两张抖动后恢复、连击清零、播失败音。
- 全部配完通关，播通关音并提示用时与得分。
- 顶部实时显示：用时、得分、连击、进度。

## 功能要点

| 模块 | 说明 |
|---|---|
| 每关对数 | 4 / 6 / 8 / 10 对四档；能玩多少对取决于词库有多少个词，不够的档位自动置灰并给出提示 |
| 词库 | 内置 6 个词（选举主题）；可粘贴录入、可从手机本地 .txt / .csv 导入（UTF-8 与 GBK 双解码）、可一键恢复默认 |
| 读词 | 顶部「读词」按钮内置总开关：开=可以朗读（点读词读全部、点英文卡自动读），关=完全静音 |
| 我的声音 | 「读词」按钮内的「我的声音 ›」可进录音面板：逐词录自己的读法（最多 6 秒）、试听、删除、清空；有录音的词播录音，没录的仍用系统朗读；录音存本机 IndexedDB、不上传 |
| 音效 | 四组共 31 种风格（点击 8 / 成功 9 / 失败 7 / 通关 7），全部用 Web Audio 实时合成，不含音频文件 |
| 设置 | 总音量、四类音效开关、口音（美式/英式）、语速、音效风格切换、各类试听 |
| 记忆 | localStorage 记住设置、词库、上次选的对数 |
| 外观 | 深绿底、淡红卡片 `#ffe3e3`、淡紫英文 `#9575cd`、金边按钮；≥8 对自动切 4 列紧凑 |

## 主提示词：做出这个网页游戏

```
你是一个前端工程师。请只用一个纯静态的 index.html 文件（内联 CSS 和 JavaScript，
不引用任何外部库、CDN、字体、图片文件、网络请求），做一个中文界面的手机端单词配对小游戏，
名字叫「碰碰乐」。要求打开即玩、离线可玩、能存本地状态。

【玩法】
1. 一个词生成一对牌：一张英文卡 + 一张与它对应的中文卡，打乱后铺成网格。
2. 点两张牌：配对成功则两张一起消失、得分 +10、连击 +1、播成功音；
   不匹配则两张抖动 0.4 秒后恢复、连击清零、播失败音。
3. 全部配完算通关：播通关音，提示用时与得分。
4. 顶部实时显示：用时（每秒走）、得分、连击、进度 x/y。

【每关对数】
- 四档胶囊按钮：4 对 / 6 对 / 8 对 / 10 对，选中态亮绿色渐变。
- 关键规则：容量 = 词库里实际有多少个词（一对牌 = 一个词）。词数不够的档位必须置灰点不动，
  并在按钮上给出"词库只有 N 个词，最多 N 对"的说明；面板里再用黄色文案写一句
  「当前词库 N 个词，最多可玩 N 对」。
- 选对数时若超过容量，起始时自动收敛到容量并同步刷新进度分母，绝不出现"进度永远差几对、
  这局打不完"的假进度。
- 记住上次选的对数，刷新后自动恢复。

【界面结构（从上到下）】
1. 顶栏：左侧方形 Logo（深绿底、金边、里面一个汉字）+ 标题「碰碰乐」；右侧 4 个胶囊小标签：
   用时 / 得分 / 连击 / 进度。
2. 按钮行（一行放满，等分宽）：「词库」「设置」「提示」「读词」+ 读词按钮内部右侧一个开关
   （见下）。窄到 360dp 也不能挤爆、不能换行、不能文字被裁。
3. 牌面：3 列网格；对数 ≥8 时自动切成 4 列紧凑模式（字号和高度略缩）。
4. 底部固定面板：标题「每关对数」→ 四个对数胶囊 → 居中放一个「重开」按钮 →
   说明文字与提示行。

【配色（严格用这套，深绿底 + 淡红牌 + 淡紫英文）】
- 页面背景：#1a3b2b，用径向渐变从 #244232 过渡到 #0c1a12
- 卡片底色 #ffe3e3（淡红）；中文文字 #222；英文文字 #9575cd（淡紫）
- 选中态：#ff4d4f 红框 + 红色光晕
- 按钮：深绿渐变 #2f4b3c → #3b6452，金边 #b89c4f，文字白色
- 强调绿 #4fbf7a；金色 #d8b868 / #e9d39b；提示黄 #e9b44c
- 卡片圆角 14px、投影柔和；字体用系统 UI 字体栈

【「读词」按钮里的开关（重点）】
- 整个按钮是一个容器：左边是白色文字「读词」，右边是一个小号胶囊开关（34×18，滑块 14，
  开时绿色渐变、关时灰色），整体外观仍是一个深绿金边按钮。
- 语义是"读词总开关"：开 → 点「读词」会把所有未消失的英文卡逐条朗读（每条间隔 700ms），
  点英文卡也会自动朗读；关 → 什么都不读（点「读词」、点英文卡都完全静音）。
- 开关状态与设置里那条勾选是同一个变量，双向联动，改动立刻写进 localStorage。
- 点文字只朗读、点开关只切换，两者不能互相触发。
- 按钮内部再放一行小号金字入口「我的声音 ›」，点开是录音面板（见下）。

【我的声音（用自己的录音替代机器朗读）】
- 独立面板：按当前词库逐条列出（英文、中文、已录/未录），每条三个按钮「录音 / 试听 / 删除」；
  底部「清空全部录音」（要点两次才执行，第一次文案变「再点一次=清空」，3 秒不点自动复原）与「关闭」。
  面板里写明：录音只存在这台设备、不上传、换设备或清缓存会丢。
- 录音：getUserMedia + MediaRecorder，点一下开始、再点一下结束，最多自动停 6 秒；
  没拿到麦克风权限、或环境不支持 MediaRecorder 时都要给出可读的提示。
- 存储：放 IndexedDB（库 `pengpengle_voice`、表 `voices`、键=英文单词小写，值含 blob/mime/时长/时间），
  不要塞 localStorage；另加内存缓存，避免每次朗读都查库。
- 播放优先级：有录音播录音、没录音走系统朗读；"读词"逐条播时要等录音真正播完再下一条（9 秒超时兜底）。
- 安卓壳必须补 RECORD_AUDIO 权限、onPermissionRequest（只放行 RESOURCE_AUDIO_CAPTURE）与
  onRequestPermissionsResult，否则手机上点录音会无声失败。

【底部「重开」按钮】
- 水平居中，淡红渐变底（#ffeaea → #ffdcdc）、深红文字 #8a2323、圆角 18px、
  字号 22px、最小宽 198px、内边距 15px/36px（比常规按钮大约 1.5 倍）。
- 点下去要有两重回馈：先播一次"卡片点击"音效（受设置里的音效开关与总音量控制），
  同时做 1 → 0.9 → 1 的回弹缩放动画（约 0.28 秒），然后重排牌面、计时归零。

【词库弹窗】
- 一个多行文本框，一行一条「英文, 中文」，占位示例若干条。
- 三个按钮：加载/保存、从文件导入、恢复默认词库。
- 从文件导入：文件选择器接受 .txt/.csv；先按 UTF-8 解码，若出现替换字符（乱码）再按 GBK 解码，
  保证 Windows 记事本存的 ANSI 中文词表不乱码。
- 解析规则：分隔符兼容半角逗号、中文逗号、顿号、制表符、竖线、分号、空格；# 开头为注释；
  同一英文去重；解析不了的行统计为"跳过 N 行"；少于 4 条直接拒绝并提示。
- 导入或加载成功后写 localStorage，刷新/重开仍在；恢复默认回到内置 6 个词。

【内置默认词库（6 条，够一局 6 对）】
nominate=提名、ballot=选票、rally=集会、election=选举、resign=辞职、voter=选民

【设置弹窗】
- 总音效音量滑杆（默认 120%）；
- 四个勾选：卡片点击音、配对成功音、配对失败音、通关音；
- 一条「读词与自动朗读（与顶部读词开关同一个）」勾选；
- 口音下拉：美式 en-US / 英式 en-GB；朗读语速滑杆（默认 0.70）；
- 试听按钮：试听朗读、试听点击、试听成功、试听失败；
- 四组「音效风格」下拉（清单见下），每组旁边可试听；
- 保存并生效 / 关闭 两个按钮。

【音效（全部用 Web Audio API 现场合成，不要任何音频文件）】
四组风格，共 31 种：
- 卡片点击（8）：水滴 drop、轻咔 click、叮咚 ding、气泡轻响 pop、轻点 tap、
  木鱼叩响 wood（三角波 620→430Hz，0.09s）、小铜铃 bell（正弦 1560Hz，0.22s）、
  马林巴 marimba（三角波 880→520Hz，0.14s）
- 配对成功（9）：星尘碎铃 stardust、wow 上升 wow、清脆闪光 sparkle、悦耳钟声 chime、
  明亮上扬 bright、短凯旋 triumph、柔滑上滑 glide（正弦 420→1180Hz，0.34s）、
  叠音三连 stack（正弦 784/988/1175 错峰 0.03s）、竖琴扫弦 harp（三角波
  659/880/1047/1319 错峰 0.035s）
- 配对失败（7）：低沉下滑 down、闷咚 thud、刺耳警告 warn、嗡嗡错音 buzz、叹气下滑 sigh、
  低频嗡鸣 lowbuzz（锯齿 92Hz，0.4s）、双段下滑 doublefall（正弦 520→300 于 0s、
  360→170 于 0.22s）
- 通关（7）：铜管号角 horn、欢庆上扬 cheer、明亮和弦 bright、短号花腔 fanfare、
  连续攀升 ascend、厚重复调 epic（三角波两组三和弦 [392,523,659]、[494,659,784]
  错峰 0.28s，各 0.7s）、喜钟长鸣 longbell（正弦 1047/1319，错峰 0.06s，1.1s）
体积感统一：所有音量都过一层总音量系数，最高不超过 0.3，避免炸耳。

【朗读】
- 用浏览器 speechSynthesis；口音与语速取自设置；读词开关关闭时一律不发声。
  注意：判断要放在朗读函数入口，这样"手动点读词"也受总开关控制，不会出现关了还响。

【本地存储（键名固定）】
- pengpengle_setting：音量、四个音效开关、读词开关、口音、语速、四组音效风格
- pengpengle_wordbook：当前词库数组 [{en, cn}]
- pengpengle_pairs：上次选的对数

【布局红线（这几条最容易翻车，必须做到）】
1. 底部面板是 fixed 浮在页面底部，必须按它实际高度给牌面动态加下边距，
   否则最后一行牌会被面板压住点不到；滚动到底时最后一行必须完整可见。
2. 任意档位都必须能真正打完（进度分母 = 实际可配对数）。
3. 360dp 窄屏下按钮行不换行、文字不裁切：读词按钮内「文字 28px + 间距 4px + 开关 34px +
   左右内边距 8px = 74px」，四等分每格约 78px，刚好放得下。
4. 任何 alert 提示都必须能被 WebView 显示（打 APK 时要补 shell 的 onJsAlert）。

【交付要求】
- 只交付一个 index.html，双击即开、断网可玩。
- 自查：语法检查通过；6 个默认词时 4/6 可点、8/10 置灰且提示正确；导入 12 条能选 10 对
  （20 张牌、4 列紧凑）；点掉一对进度 1/10、得分 10；刷新后词库与对数仍在；
  读词开关关掉后点读词与点卡片都不出声；重开能重排并归零计时。
```

## 追加提示词：做成能装到手机桌面的网页版（PWA）

```
在刚才那个 index.html 之外，再补三个文件，并让 index.html 引用它们：
1. manifest.json：name/short_name 用「碰碰乐」；display 用 standalone；orientation 竖屏；
   background_color #244232；theme_color #1a3b2b；icons 声明一张 512×512 的 PNG（any + maskable）；
   补 scope、lang: zh-CN、start_url。
2. icon.png：512×512，要清晰不糊（从大图缩，不要拉伸小图）。
3. sw.js 用「版本化缓存」：
   - 导航请求（index.html / 站内页面）走「网络优先，失败回落到缓存」，保证改完能立刻看到新版；
   - 静态资源（icon、manifest）走「缓存优先」；
   - 安装时 skipWaiting、激活时 clients.claim，并清掉旧版本缓存。
   在 index.html 里注册时加 { updateViaCache: 'none' }，并补
   rel="icon" / apple-touch-icon / apple-mobile-web-app-capable / apple-mobile-web-app-title。

验收：浏览器里刷新应受 SW 控制；断网后从桌面图标启动仍能打开；改版后旧缓存不粘人。
```

## 追加提示词：打成安卓 APK（没有 Gradle 的机器也能打）

```
把这套网页封装成一个可以直接安装的安卓 App，要求：
1. 单 Activity + 全屏 WebView，竖屏锁定，无标题栏；minSdk 26、targetSdk 34；
   应用名「碰碰乐」；图标用同一张 512 图标缩成 48/72/96/144/192 五档 mipmap。
2. 页面和图标全部打进 assets/，不申请 INTERNET 权限（完全离线）。
   页面用 https://app.local/index.html 加载，由 WebViewClient.shouldInterceptRequest
   从 assets 拦截返回并按扩展名补 MIME，避免 file:// 的同源与存储限制。
3. 必须打开 domStorageEnabled（游戏要存 localStorage）、
   mediaPlaybackRequiresUserGesture = false（播报与音效不需要先点）。
4. WebView 里没有 speechSynthesis，要做桥：给页面 head 注入一段 shim，
   覆写 SpeechSynthesisUtterance 和 speechSynthesis，转发到 Java 侧
   AndroidTTS.speak(text, rate, volume, lang) / stop / isReady；en-US、en-GB 分别
   映射到美音/英音，语速音量原样透传。
5. WebView 默认不弹 alert，必须实现 onJsAlert（弹 AlertDialog，确定后 result.confirm()，
   不可取消），否则"已导入 N 条"这类提示会静默消失。有文件导入就同时实现
   onShowFileChooser（ACTION_GET_CONTENT + onActivityResult 回传）。
6. 打包前对页面做一次"壳化处理"：删掉 manifest 引用、去掉 serviceWorker 注册块、
   注入上面的 TTS shim（脚本要对锚点做断言，head 结构变了要同步改）。
7. 无 Gradle 的手工链路：aapt2 compile → aapt2 link（-A assets）→ javac
   （-source 8 -target 8 -bootclasspath android.jar）→ d8（--min-api 26）→
   zip 塞 classes.dex → zipalign -f 4 → apksigner sign。
8. 签名必须固定用同一个 keystore（换签名会导致"装不上、只能先卸载"）。
   每次出新版把 versionCode 加 1、versionName 对应升级，用户就能覆盖安装。
   页面里若用到录音，清单要加 RECORD_AUDIO，并在 WebChromeClient 里实现 onPermissionRequest
   只放行音频采集、onRequestPermissionsResult 回传用户选择。
9. 出包后自查：apksigner verify 打印证书指纹一致；aapt2 dump badging 里
   versionCode / versionName / application-label / 5 档图标 / launchable-activity 正确；
   把 APK 里的 assets/index.html 解出来，grep 关键改动是否都在。
```

## 两个容易踩的坑（写在这里免得以后忘）

1. 浏览器自动化脚本看不到页面里的内部变量（隔离世界），想知道"读词开关到底拦没拦住朗读"，
   得做一份带 DOM 可见计数钩子的临时副本再测，别把"探测不到"当成"功能失效"。
2. 用 GitHub 网页上传时，附件挂到隐藏 input 后如果文件列表仍是空状态，要在页面内对
   `input[type=file]` 依次派发 `input` 与 `change` 事件（`bubbles: true`），否则提交会静默丢文件。
